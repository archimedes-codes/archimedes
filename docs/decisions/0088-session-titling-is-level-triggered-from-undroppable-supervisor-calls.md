# Titling is level-triggered from undroppable Supervisor calls, and the UI recovers a live title on focus

An amendment to ADR 0086, which it does **not** supersede: the two-stage `title_stage` ladder, the `{id}-title` wire isolation and the conditional `WHERE title_stage = ?` write all still stand. What changes is *where the ladder gets re-consulted* — and ADR 0037's consequence *"NO retry, sleep, or re-read loop was added"* for the transcript/`agent_end` ordering race is amended with it.

Issue #143 reported that a generated title reaches the sidebar late or never, and that a restart fixes it. Two independent single-point-of-failure routes turned out to be the cause, and we fixed both by **adding a second route** rather than hardening the first:

1. **The backend trigger was edge-triggered off one droppable frame.** `agent_end` is titling's only trigger (`agent/session/router.rs`), and it rides `tokio::sync::broadcast::channel(256)` (`agent/worker/client.rs`), whose `Lagged` arm logs and `continue`s (`agent/worker/manager/pump.rs`) — a slow pump drops the frame and titling never fires for that turn. We now also call the existing `SessionManager::maybe_name_session` from two ordinary Supervisor function calls that cannot be dropped: at the top of `send_prompt_with_images` (after the turn-in-flight guard) and in `close_session` before `detach`. ADR 0037's consequence *"NO retry, sleep, or re-read loop was added"* for the transcript/`agent_end` ordering race is **amended**: there is still no retry, sleep, or re-read, but the same guard ladder is now re-consulted from two further sites, so a lost frame is caught up at the next prompt or at close instead of being permanent.
2. **A live row's title had exactly one route to the UI.** `listSessions` runs once at boot, so the `session-titled` push was a live session's only title source and a missed frame stayed stale until restart. `mergeRefreshedSessionRows` now carries `title` in a **second pass**, deliberately outside its `contextUsage`/`configOptions` live-skip, and a new `useSessionTitleRecovery` hook re-runs `listSessions(true)` on `window` focus and on a revealing `visibilitychange`.

We also decided **not** to reorder the Worker's two stdout writers, and **not** to emit `agent_end` on cancelled or failed turns. Titling stopped/failed turns falls out of the nudges for free: the cancelled turn's user row is already persisted at `begin_turn`, so the excerpt is built from the user line alone — a shape the guard ladder already supports.

**Why:** the cheap correct fix is to over-call an operation that is already idempotent. `maybe_name_session` declines at every guard while consuming nothing (documented at its own head comment: *"Every early return consumes NOTHING: no failure counted, no `in_flight` set"*), its `in_flight` claim is taken under the write lock, and ADR 0086's `WHERE title_stage = ?` catches the write race — so calling it from more sites is free, and no new state is needed to make it safe. The same argument decides the frontend: `titleSession`'s "rewrite every list that holds the id, keep the same array reference otherwise" rule already existed, so a refresh only had to reuse it.

**Considered Options**

- **Merge the Worker's two outbound queues so `agent_end` cannot precede the transcript rows (rejected).** The split is deliberate: `RpcEvent`s ride an `mpsc::unbounded_channel` pumped by a spawned task (`worker/core.rs`), store/sink frames ride a second unbounded channel drained by the main loop, and both take the same stdout mutex — which gives per-line atomicity and no ordering between them. `tests/worker_e2e.rs` states this in prose and pins it with a `wait_for_rows` poll helper. Making the order total is a Worker-side protocol change with persistence risk, and it would not fix the loss that actually bites, which happens a hop later in the Supervisor's `broadcast`. Rejected: cost and risk land on every frame to serve one naming hook.
- **Carry the excerpt in `agent_end`'s payload (rejected).** The `messages` field is already dead weight — the router matches `agent_end { .. }` and discards it, and `normalize.rs` produces no frame for the event — so it is real estate. Rejected anyway: it is still a droppable frame, so it fixes the read race and leaves the drop.
- **Emit `agent_end` from `settle_cancelled` / `settle_error` (rejected).** This is the tempting one-line route to titling stopped turns, and it is wrong twice. Two tests forbid the frame on failure paths and encode real semantics — *"an exhausted empty turn is not a clean stop"* (`loop/tests/turn_lifecycle.rs`), plus its twin in `loop/tests/compaction_overflow.rs` — and a frame is the wrong instrument regardless: it re-enters the same droppable path. The Supervisor-side nudge titles the same turn without touching the frame contract.
- **A `title_due` query command the frontend calls on focus (rejected).** Also undroppable, and it works — but it adds a Tauri command, a capability entry, and a TS wrapper to express "run the naming pass if it is due", which `maybe_name_session` already decides correctly from persisted state. Calling it from inside the prompt and close paths needs no new surface at all.
- **Re-run `setHistorySessions` on focus (rejected).** Its own comment forbids it — *"Boot-only: do NOT re-run this mid-run (re-splitting would drop sticky live+archived entries and silently un-archive on the next close)"* — and a test pins the sticky pair it would destroy. `mergeRefreshedSessionRows` is the only mid-run refresh that touches no membership, which is why the title pass went there.
- **Poll on a timer, or throttle the focus handler (rejected).** Focus-driven is the requirement; a timer re-introduces the staleness window this is meant to close, and a debounce only hides the overlap the `inFlight` guard already handles honestly.

**Consequences**

- **A fetched row may only overwrite a title with another non-empty title, in the live and the stored lists alike.** `list_sessions` legitimately returns `title: NULL` for a row the store already labels, so a null-tolerant merge would erase a correct label and convert a stale-label bug into a lost-label bug. `SessionInfo.title` is `title?: string | null`, so the null is a real wire shape, not a hypothetical; it has its own tests for the live row and for a stored row, and the hook suite re-pins it through the real merge rather than a spy.
- **The live-skip in `mergeRefreshedSessionRows` is now field-specific, and the two halves must not be unified.** It stays correct for `contextUsage`/`configOptions` because the store's per-id map wins over a row there; it is wrong for `title`, which has no map and whose live-row source was until now only the push. Anyone tempted to collapse the two passes back into one loop should read the interface comment first.
- **`send_prompt` now runs the guard ladder on every prompt.** Guard 3 early-outs at `title_stage >= 2` *before* the transcript read, so the residual cost is one settings load, one row read and one transcript load for an **untitled** session only.
- **A stopped session can now acquire a title it previously never would**, derived from the user line alone if the turn produced no assistant row. This is intended — a session the user stopped is still a session they named — but it makes title quality on truncated first turns visible for the first time. If those read poorly the fix is prompt-side, not a new guard.
- **Every integration fixture that drives `send_prompt`/`close_session` on a session with a persisted user row must now disable naming.** `session_naming_enabled` is `#[serde(default = "default_true")]`, `SessionManager::new` defaults `provider_factory` to the production `build_provider`, and `fake_worker` emits no `agent_end` at all — so before this change those suites never reached the naming pass, and after it they would issue a real HTTP request. `tests/session_native.rs` and `tests/ipc.rs` set `"sessionNamingEnabled": false` for that reason. A red there showing an unexpected provider request is this, not a flake.
- **The naming pass no longer writes to stderr.** Its diagnostics go through `debuglog::log`, i.e. the same single `ARCHIMEDES_DEBUG` switch as the rest of the Supervisor's log, because in a bundled app launched from a desktop entry `eprintln!` has no reader at all. Message texts are unchanged so existing greps keep working.
- **A focus refresh adds reads, not writes**: `listSessions(true)` only. It must never re-call `sessionRecency()` or `listSpaces()` — a test pins that boot fetches `sessionRecency` exactly once, and `setSpaces` is separately boot-only because it re-seeds trust and can move the selected tab.
